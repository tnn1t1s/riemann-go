# riemann-go

`riemannd` is a single-node stream-processing monitor generated from `SPEC.md`. The core packages are `internal/event` (the event model and expression environment), `internal/exprs` (expr-lang compilation with a closed name set and boolean-typed predicates), `internal/rule` (rule documents, path-addressed compilation, the nine combinators), `internal/index` (per-partition last-event index with a deadline heap), `internal/engine` (partition loops, the global loop, timers, ring, bounded sink queues, rule store, dry run, subscribers) and `internal/params` (the `SCALE.md` parameters behind `--set`). The adapters are `internal/sinks/ntfy`, `internal/sinks/influx`, `internal/httpapi` and `internal/selfobs`; `cmd/riemannd` wires them. Start it with every required flag, for example `riemannd --listen :5555 --ntfy-url http://127.0.0.1:19090 --ntfy-topic alerts --influx-url http://127.0.0.1:19091 --influx-org medios --influx-bucket riemann --rules rules.json`; the ring and the index are in memory and lost on restart. Decisions marked `SPEC-GAP` in the source: an absent `initial` on `changed-state` reads as `""`; `coalesce` is refused under `host,service` as well as `host`; a binding is compiled once with the `events` visibility of its first reference; `by` forks keyed on fields other than host and service are never freed; a delivery the sink refuses counts as `dropped` so the accounting identity closes; the global loop's inbox borrows `shard.inbox_capacity` and reports as `global`; rule versions continue past a delete; the dry-run index stub does not synthesize expiry; SSE frame names are `snapshot`, `event` and `lagged`; the self-observation host is the process hostname and the fork counters are `riemann.rule.forks_live` and `riemann.rule.forks_freed`; a boot-time rule that does not compile is fatal; `engine.shards` is accepted by `--set` with `--shards` winning; and a non-string result assigned to a string field by `set` is rendered with `%v`.
